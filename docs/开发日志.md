# 开发日志

## 2026-08-27：项目规划

- 创建 LabOpsPanel 仓库并完成首版需求分析。
- 确定“中心控制端 + 受限主机 Agent”的建议架构。
- 将用户目录迁移和新硬盘初始化定义为带预检、校验、审计及回滚的高风险状态机任务。
- 当前仅包含文档和开发规范，尚未开始编码。

## 2026-08-27：收敛为本机按需运行

- 根据使用场景移除中心控制端、远程 Agent、多机管理、复杂角色和审批设计。
- 数据库固定使用 SQLite，程序仅监听本机回环地址并按需启动。
- 批量用户输入增加 XLSX 和空白字符分列的文本粘贴方式。
- 增加随机密码生成规则与 Ubuntu PAM 密码策略的读取、修改、验证和恢复设计。
- 增加 SSH 公钥格式校验、指纹去重、原子写入及所有者和权限校验设计。

## 2026-08-27：明确系统、GPU 与迁移需求

- 兼容性范围明确为 Ubuntu 22.04、24.04 和 26.04 LTS，账号默认按普通本机账号处理。
- NVIDIA GPU 页面调整为 nvtop 风格，展示进程所在 GPU、显存和可获取的进程利用率，并明确整卡带宽不能伪装成进程带宽。
- 文本用户导入确认中文名不含空格，初始密码必须导出。
- 未知文件系统先做能力识别，未验证的网络、加密或特殊文件系统不开放迁移。
- 用户 home 迁移改为终止 UID 全部进程、检查空间、原地 rename、rsync、校验、建链接、人工试验和独立确认清理的顺序。

## 2026-08-27：阶段 1 只读原型骨架

- 创建 Python 3.12、FastAPI、SQLAlchemy、React、TypeScript、Vite 和 Ant Design 工程骨架，依赖分别由 `uv` 与 npm 管理。
- 提供统一的 `labopspanel` 启动命令，自动选择可用端口并限制为回环地址；每次启动生成随机会话令牌，所有 API 均校验令牌。
- 初始化仅启动用户可访问的 SQLite 数据目录和文件，当前只保存非敏感应用配置模型，不持久化系统账号或高频指标。
- 实现系统、CPU、内存、挂载点、本机账号和 sudo 组来源的只读采集，使用 UID/GID 关联账号。
- 实现 NVML 能力探测；本机没有 NVIDIA GPU 时明确返回不可用状态，CPU、内存、账号和存储接口继续正常工作。
- 增加回环限制、令牌拒绝、SQLite 权限与幂等初始化、稳定账号身份及 GPU 缺失降级测试；未执行任何特权、磁盘或用户写操作。

## 2026-08-27：资源刷新与首版范围确认

- CPU 和内存改用独立只读接口每 2 秒刷新；刷新失败时保留最后一次有效值并显示提示。
- 本机账号列表不再展示 shell 为 `nologin` 的账号，并增加不区分大小写的用户名搜索。
- 首版架构范围确定为 `amd64/x86_64`，GPU 测试基线确定为 RTX 3090 及更新代际。
- 随机初始密码默认 20 位并排除易混淆字符，不强制首次登录改密，也不管理周期性密码到期。
- home 迁移首版仅将本地 ext4 纳入候选白名单；新盘初始化范围确认为空盘 GPT + ext4，所有写操作仍须先完成专项安全测试。
