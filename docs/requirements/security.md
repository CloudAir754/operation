# 安全设计与残余风险

本文记录首版的安全边界、实现方式与已知残余风险。任何新增远程写操作都必须先补充本文件与
`acceptance.md` 的验收条目。

## 1. 威胁模型

LabOpsPanel 运行在管理员自己的 Windows 工作站上，信任本机当前登录用户；不信任网络对端，
也不假设远端主机配置正确。主要风险来自：

- 误操作导致远端服务/网络中断，或失去 SSH 访问能力。
- 凭据泄漏（sudo 密码、私钥、会话令牌）进入数据库、日志或前端。
- 远端输出过大、命令挂起或交互式提示导致本机资源耗尽。
- 通过 SSH 配置解析差异绕过既有限制（例如错误地解释 `ProxyJump`/`ProxyCommand`）。

## 2. 网络暴露面

- 默认只绑定 `127.0.0.1:8765`；`Settings` 在启动时校验，非回环地址会被拒绝，除非显式设置
  `LABOPS_ALLOW_REMOTE_BIND=true`。
- 首版无登录、无多用户 RBAC：任何能访问该端口的本机进程都等同于管理员。不要将端口映射到局域网。
- 静态资源仅从 `frontend/dist` 提供；SPA 回退对路径做 `relative_to(dist)` 校验，拒绝路径穿越；
  `/api/*` 不参与回退。

## 3. 凭据

- sudo 密码使用 Windows DPAPI（当前用户作用域）加密后写入 `server_secrets.ciphertext`；
  数据库中没有明文，API 从不返回明文，前端也从不回显。
- 解密只发生在执行需要提权的步骤前，密码通过 **stdin** 传给远端 `sudo -S -p ''`，
  不进入 argv、进程列表快照、任务参数或审计日志。
- `sudo` 的时间戳缓存可能让同一会话内的后续命令免密；这是远端 sudo 的既有行为，应用不额外延长缓存。
- DPAPI 密文与 Windows 账户绑定：数据库文件复制到其他账户下无法解密，会返回明确的解密失败。
- `LABOPS_SECRET_BACKEND=disabled` 只用于排障，会禁用凭据后端并让需要 sudo 的动作返回 503。

## 4. SSH 行为

- 导入自 OpenSSH 配置的主机只传别名，并带 `-F <config>`，让 OpenSSH 完整应用 `Include`、
  `ProxyJump`、`ProxyCommand`、`IdentityFile`，避免自行拼接导致行为偏差。
- 固定 `BatchMode=yes` 与 `NumberOfPasswordPrompts=0`：不进行交互式认证，不会卡在密码提示上。
- `StrictHostKeyChecking=accept-new`：首次连接接受新主机密钥，之后密钥变化会失败并给出诊断。
  这是可用性与安全性的折中；高安全环境应预置 `known_hosts`，并把该选项改为 `yes`。
- 连接超时、命令超时、取消均会终止本机 ssh 子进程；远端进程由 SSH 关闭连接时回收。

## 5. 远程写操作

- 只有固定动作白名单可以执行；参数模型 `extra="forbid"`，未知字段直接 422。
- 每次提交写操作都需要 `confirm=true` 与 `idempotencyKey`，重复键返回 409，避免重复执行。
- 服务名经过正则白名单校验并规范化；受保护服务（`ssh*`、`systemd-*`、`dbus*`、`network*`、
  `netplan*`、`polkit*`、`auditd`、`ufw`、`firewalld` 等）禁止 `stop`/`disable`/`mask`。
- 服务动作固定为“预检 → 执行 → 校验”三步，执行前读取 `LoadState`，执行后校验 `is-active`/`is-enabled`。
- 任意命令入口默认关闭；启用后仍需 Bash `-n` 语法检查、高风险确认、超时、输出截断与幂等键。
- 输出按流截断（默认 256 KiB），任务尾部最多保留 4000 字符；被截断的探针输出视为采集失败。

## 6. 数据与日志

- SQLite 位于 `%LOCALAPPDATA%\LabOpsPanel`，不进源码树；WAL、外键与 `busy_timeout` 已开启。
- 快照包含远端系统信息（主机名、磁盘、服务列表），属于敏感基础设施数据：只保存在本机用户目录，
  每台主机最多保留 50 份。
- 审计记录动作、目标、时间、结果与错误摘要；不记录密码、完整输出或私钥内容。
- 任务参数会落库（如服务名、日志行数），因此严禁把密码类参数放入动作参数。

## 7. 依赖与构建

- Python 依赖由 `uv` 锁定（`uv.lock`），前端由 `package-lock.json` 锁定。
- 前端生产构建产物由后端同源提供，不引入 CDN、外部脚本或遥测。
- 生产模式关闭 FastAPI `/api/docs` 之外的额外端点；文档端点仅本机可访问。

## 8. 阶段三：观测与扫描的安全边界

- 指标、GPU、用户与空间扫描全部是**只读**操作：只执行固定探针，不拼接用户输入的命令；
  探针参数只包含挂载点、深度、开关标记，且通过 shell 引号转义并拒绝控制字符。
- 空间扫描的挂载点必须与远端 `/proc/self/mounts` 的 allowlist 精确匹配（fail closed），
  不接受任意 root 路径；`children` 接口再次校验路径位于扫描挂载点内，拒绝 `..` 与越界。
- 扫描不会读取文件内容，只做 `lstat`/目录枚举；`deleted-open` 只读取 `/proc/<pid>/fd` 的链接与
  `stat` 信息，跨用户不可见时保持缺失而不是猜测。
- 输出与资源上限：探针单模式输出不超过 240 KiB（传输层默认 256 KiB 截断即视为失败）、
  扫描节点上限 1200（探针）/3000（结果）、每主机并发扫描 1、超时默认 180 秒、
  SSE 节点分块 200、每主机保留最近 50 次扫描结果。
- 取消会终止本机 ssh 子进程；应用重启把未完成扫描标记为 `interrupted`，不自动重试。
- 用户模式不读取 `/etc/shadow`，不回传 sudoers 原文；`sudoEffective` 仅对当前 SSH 用户执行
  `sudo -n true`（不使用保存的 sudo 密码、不触发交互），其他用户保持 `unknown`。
- 指标采集与扫描不使用 sudo 密码；只有既有的服务管理动作会在需要时使用 DPAPI 保存的密码。
- 扫描结果包含路径、用户名与 UID 等基础设施信息，与快照一样只保存在本机用户目录的 SQLite 中，
  并受历史保留上限约束。

## 9. 阶段四：账户生命周期的安全边界

- **两层密码严格分开**：
  - 运维 sudo 密码：只存 Windows DPAPI 密文，明文只在提权步骤执行前存在于内存，
    通过 stdin 传给远端 `sudo -S -p ''`。
  - 目标账户登录密码：由后端 `secrets.SystemRandom`（`os.urandom`）生成，
    只保存在**本进程内存**，通过 `POST /api/account-batches/{id}/reveal` 一次性下发，
    读取后立即从内存删除；不写数据库、不写审计、不写日志。
- 生成密码进入远端只走「非 sudo 暂存 0600 文件 → sudo `chpasswd < 文件` → 无条件删除」，
  密码字符串不出现在任何 argv 中；用例 `test_batch_password_never_enters_argv` 覆盖该约束。
- 手工指定的目标账户密码必须先通过合并了系统下限的规则校验，弱密码直接 422 拒绝。
- 系统密码策略写入：只改 `pwquality.conf` 的受管键与可识别 PAM 行的行内参数；
  无法识别的行、注释、未知键原样保留；PAM 行有歧义时该字段只读。
  写入前把 `/etc/security/pwquality.conf`、`/etc/pam.d/common-password`、
  `/etc/pam.d/common-auth` 备份到 `/var/backups/labopspanel/`（0700），
  写入后重新读取比对，失败立即用备份恢复并标记 `failed`。
- 目录迁移：a) 只允许本地 ext4；b) 迁移前锁定账号并确认无残留进程；c) 先在同父目录内
  `mv -T` 改名保留备份，再 `rsync -aHAX --numeric-ids --one-file-system` 复制；
  d) 校验文件数/目录数/逻辑大小/实际占用/目标盘可用空间变化；e) 只有全部通过才建符号链接；
  f) 备份保留到管理员显式清理，清理前复核任务 ID、备份路径、目标路径与当前链接关系。
- 迁移与空间分配的所有远端写操作都走 `sudo -S`；参数（账户名、UID/GID、路径、链接名）
  先经过白名单校验与 shell 引号转义，路径拒绝 `..`、控制字符与超长输入。
- 迁移/策略/批次的每条审计只记录动作、目标、结果与错误摘要，不记录密码与文件内容。
- 自动回退：迁移后功能验证失败会重新冻结账号、删除符号链接、把备份改名回原路径并恢复登录状态，
  结果写入任务 `result.autoRollback`，不会静默留下半完成状态。

## 10. 残余风险

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 本机进程可调用 API | 回环端口无认证 | 仅个人工作站使用；不开放端口转发 |
| 首次主机密钥被接受 | `accept-new` 无法验证首次身份 | 预置 `known_hosts`，或改为 `yes` |
| sudo 密码可在内存中被读取 | 解密后短暂存在于进程内存 | 仅在本机受信环境运行；不启用崩溃转储 |
| 远端 sudo 规则过宽 | 应用只按动作调用 sudo，无法审计远端 sudoers | 远端最小权限 sudoers，只允许 systemctl/journalctl |
| 交互式服务停止导致失联 | 受保护列表是静态白名单 | 保护 `ssh*`/`network*`；其他服务需人工确认 |
| 输出被截断导致信息不全 | 上限保护本机资源 | 提示 `truncated`，需要完整输出时用远端工具 |
| 扫描结果可能不完整 | 权限不足、深度/节点上限会导致 `incomplete` | 界面标注不完整；需要时用更高权限或更小范围重扫 |
| 进程级 GPU 利用率不可得 | `nvidia-smi` 不提供按进程利用率 | 返回 `null` 与 `perProcessUtilization=false`，显示 `N/A` |
| GPU 仅支持 NVIDIA | 首版未实现 AMD/Intel 适配器 | 无 `nvidia-smi` 时返回 `unavailable`，不伪造数据 |
| 密码策略影响全局 | 改 `pwquality.conf`/PAM 参数会影响该主机所有本地用户 | 必须二次确认、展示 diff、备份并在验证失败时自动恢复 |
| 生成密码可能被旁观 | 一次性下发后只能人为记录 | 只显示一次、读取即清除、界面提示安全分发并及时改密 |
| 迁移期间的新写入 | 切换后到回退前写入新位置的数据只存在于新位置 | 回退默认拒绝，需显式 `discardNewData=true` 才丢弃 |
| 迁移空间估算偏差 | 压缩、稀疏文件与 reflink 使实际占用与估算不同 | 按 `st_blocks` 保守估算 + 可配置余量 + 复制前后可用空间变化校验 |
| 手工 PAM 配置不可识别 | 非规范写法的 PAM 行无法安全改写 | 该字段只读并说明原因，未知行原样保留 |
